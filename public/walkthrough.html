01

Real local jobs versus hosted automation

The app runs actual native CLI and SDK processes locally on generated trusted fixtures. It does not post comments, open PRs, auto-commit fixes or run a hosted GitHub agent job. The public repository includes offline source checks and a manual secret-dependent workflow for you to enable.

02

Bare mode is not deterministic inference

--bare skips discovery of hooks, skills, commands, subagents, plugins, MCP, auto memory and CLAUDE.md. Explicit options can still supply context. It reduces ambient configuration differences; it does not guarantee identical text, eliminate managed policy or create an OS sandbox.

03

A controlled discovery comparison

The ordinary CLI case sees the benign fixture CLAUDE.md marker AUTO-DISCOVERY-55. Context adds --bare and a reviewed rules file containing CI55-EXPLICIT. The trusted fixture README separately identifies the project as CI55-DEMO. No real user configuration or untrusted PR instruction is deliberately imported.

04

CLI JSON and invalid schema

CLI stdout is the actual JSON result in ordinary cases. Schema uses a real invalid JSON Schema type and preserves the actual stderr validator diagnostic and nonzero native process exit. It does not invent a model outage or synthesize a result object when stdout is not JSON.

05

dontAsk is an unattended gate

Unapproved calls are denied rather than waiting for a user. Deny submits only the harmless known fixture command once, allowing the native permission mode to reject it; the marker file must remain absent. Other unreviewed commands are blocked by the host before execution.

06

A deliberately small lint task

The generated fixture uses a tiny regex teaching linter, not ESLint. The only permitted edit is var message to const message in src/greeting.js. Hooks reject arbitrary edits and shell combinations. The parent verifies exact file contents before running independent trusted checks.

07

Native success differs from job success

Gate leaves the lint issue intact, lets the native read-only SDK task succeed, then fails the real lint check. The worker must exit 1. Fix must have the expected diff plus independent lint/test exit 0 before its actual process may pass. The UI displays actual and reported process exits separately.

08

Secrets and trusted runners

The key lives only in private .env or a shell. Non-model verification subprocesses do not receive it. Never give credentials to untrusted PR code, repository hooks, package scripts or arbitrary agent-generated programs. Tool policies are not OS isolation; production runners need appropriate sandboxing, identity and repository trust controls.

09

Bound work and costs

CLI tasks allow six turns, or one for the limit case, with a $0.30 estimate threshold. SDK read tasks allow six turns and fix allows ten, with a $0.35 threshold. Worker timeout is five minutes. Estimates can overshoot before checks and are not hard prepaid caps.

10

Workflow triggers and permissions

ci.yml checks source on push/main and pull requests without API secrets. agent-demo.yml is manual, main-only and contents-read; the selected input is an enum passed through an environment variable, not interpolated as shell code. Checkout does not persist credentials. No recurring schedule is enabled.

11

Claude Code Action alternative

The optional reference uses anthropics/claude-code-action and repository secrets, with explicit CLI arguments. It remains outside .github/workflows until you review official GitHub App setup and choose to enable it. Mention-based issue/PR actions and scheduled prompts are explained, not activated by this app.

12

Evidence and platform support

Native stdout/stderr, JSON, tool observations, independent checks and real Git diff are retained in the ignored runtime folder. Windows may need Git Bash. The pinned SDK supplies a matching platform CLI; no global claude binary or jq installation is required for the app.
